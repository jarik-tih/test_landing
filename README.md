# Кварта - лендинг для обжарки кофе

Главная задача - создать лендинг, захватывающий внимание клиентов, среди однообразного 
контента сгенерированным нейросетью. При этом не затратить много времени и 
ресурсов на его создание. 

# Создание бекенда и фронтенда:
## Ход работы и архитектурные решения

Проект развивался в три этапа: от быстрого прототипа до структурированного приложения,
готового к расширению.

### 1. Прототип (MVP)
В начале я использовал ИИ-агента, чтобы быстро собрать работающий продукт: лендинг
на HTML/CSS/JS и минимальный сервер на `http.server`. Вся логика — от роутинга
до записи в SQLite — жила в одном файле `server.py`. Это позволило зафиксировать
требования (валидация номера телефона, дедупликация, сбор UTM) и проверить поведение формы
до того, как вкладываться в структуру. 

Однако в прототипе не было внятного логирования. При ошибке было не понять, 
на каком этапе она возникла и какой HTTP-ответ ушёл клиенту — отлаживать приходилось 
по догадкам.

### 2. Рефакторинг под слоистую архитектуру
Когда бизнес-логика уже работала, я переписал сервер с упором на **Single Responsibility**.
Каждый файл отвечает за одну задачу, а зависимости идут сверху вниз:
```
app/
├─ api/ → HTTP: приём запроса, вызов сервиса, ответ
├─ services/ → бизнес-логика: дедупликация
├─ repositories/ → доступ к БД: SQL-запросы
├─ models/ → структуры данных (DTO)
├─ validators/ → проверка входа: регулярные выражения, лимиты
├─ database/ → соединение с БД
├─ config.py → лимиты, тексты ошибок, настройки
└─ main.py → точка входа
```

Что это дало:
- **Изоляция БД.** SQLite выбран для удобства запуска — файл `data/leads.sqlite3`
  лежит рядом, не требует инфраструктуры. Но благодаря слою `repositories`
  переход на PostgreSQL или MySQL затронет только `database/connection.py`
  и `repositories/lead_repository.py`. Слои `api`, `services` и `models`
  останутся без изменений.
- **Изоляция бизнес-логики.** Проверка дублей и нормализация номера телефона живут
  в `services`/`validators`, не размазаны по обработчикам.
- **Читаемость.** Изменение схемы БД не ломает API, изменение валидации
  не ломает сервис.

Также я переписал фронтенд, чтобы валидация заявки проходила на нескольких этапах:
1. На фронтенде.
2. На бэкенде.
3. Запись в базу данных.

Логирование. После рефакторинга я добавил `run.py` как точку входа с журналом
событий: в терминале видно входящий запрос, результат валидации, ответ сервера
(включая HTTP-статус) и запись в БД. Это закрыло главную боль прототипа —
теперь при ошибке сразу понятно, на каком слое она возникла.

### 3. Дублирование заявок в Telegram
После изменения архитектуры я добавил отправку уведомлений в Telegram.
Для этого создан отдельный сервис services/telegram_service.py, который вызывается
из lead_service.py после успешного сохранения заявки в базу.

Интеграция заняла минимум кода и не потребовала изменений в API, валидаторах или фронтенде. 
В чем и кроется удобство новой архитектуры - поддержке кода и добавлении новых фич.
Если Telegram недоступен или не настроен, заявка всё равно сохраняется, а клиент получает успешный ответ.

## Деплой 
При решении каким хостингом пользоваться, я исследовал какие есть бесплатные и какие у них 
ограничения в конечном итоге было решено, что фронтенд `HTML/CSS/JS` был задеплоен через Cloudflare Pages,
а для того, чтобы задеплоить бекенд и базу данных пришлось бы заплатить денег, чтобы он корректно 
работал. Бекенд можете посмотреть в коде либо ниже будет руководство по запуску локально.

## Руководство по запуску локально
1. Требования:
Установите:
- [Python 3.14](https://www.python.org/downloads/)
- [Git](https://git-scm.com/downloads)
2. Клонирование проекта
```bash
git clone https://github.com/jarik-tih/test_landing
cd <папка_проекта>
```
3. Создание и активация окружения
```
python -m venv .venv
source .venv/bin/activate
```
4. Установка зависимостей
```
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```
5. Настройка окружения

В файле .env сохраните ваши секреты, получить токен и создать бота можно у @BotFather.:
```
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_CHAT_ID=id_чата
```
6. Запуск
```
python run.py
```
